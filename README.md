# lowercase only

一扇只收小寫字母的門

## 玩法

打開頁面，想辦法讓門打開。過關後會顯示一面旗標（flag）
卡關的話，頁面底下有三段提示

原理寫在本文最後，預設收起來，不想被暴雷就先別點開

## 換一道題目

```sh
node tools/make-lock.mjs
```

會隨機產生 32 位的新答案，並印出一段 `const LOCK = {...}`，
把它整段貼回 `index.html`，取代原本的那一段。

也可以自己指定答案位元和旗標：

```sh
node tools/make-lock.mjs 1101001110 'FLAG{hello}'
```

答案位元只印在終端機上（stderr），不會寫進任何檔案，自己記好就好。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 遊戲本體，HTML、CSS、JS 都在裡面 |
| `tools/make-lock.mjs` | 產生新題目的設定（需要 Node 18 以上） |

## 安全性說明

這是解謎玩具，**不要拿這個機制來保護真正的東西**
每個字母只帶 1 bit 的資訊，32 個字也只有約 43 億種組合
頁面上的燈號本身就是答案的線索，原本就是設計給人解的

<details>
<summary>原理（暴雷）</summary>

輸入框套了 CSS `text-transform: lowercase`，不管打什麼，**看起來**都是小寫
但這只改變顯示，`input.value` 保留了原本的大小寫

- 每個字母只看大小寫：大寫 = `1`、小寫 = `0`，是哪個字母不重要
- 燈號是一排 32 bit 的「鎖」。亮 = `1`、暗 = `0`
- 要輸入的是燈號的**反向**：燈亮的位置打小寫，燈暗的位置打大寫
- 輸入和燈號做 XOR，結果是全部 `1`，燈全部亮起來，門就開了

```
燈號   0010
輸入   1101   例如 AAcF、SEsE、VOoS
XOR    1111   → ACCESS GRANTED
```

### 為什麼看原始碼也沒用

原始碼裡沒有答案，也沒有「反向」這條規則
旗標是用 AES-GCM 加密的，金鑰由答案位元經過 PBKDF2（20 萬次）推導出來
輸錯就解不開，解開了就代表答對
